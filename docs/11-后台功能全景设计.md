# 11 · 后台功能全景设计 v2

> 2026-08 起草。本文档承接并**取代** docs/10 的角色模型部分, 是后台管理全部功能的权威设计。
> 与 docs/10 相比的两个已落地变化:
> 1. **三层角色模型**(2026-08 与业务确认): 系统管理员 / 门店管理员 / 普通用户; docs/10 的"总部员工 hq_staff"已废弃。
> 2. **门店成为一级维度**: "进店工作台"模式落地(`/stores/{id}`), 会员/工单/管理员均以门店为单位组织。
>
> 文档先行, 确认后按 §7 分期实施。实现状态标记: ✅ 已上线 / 🟡 部分实现 / ⬜ 未实现。

## 1. 角色与权限矩阵(最终版)

| 角色 | 载体 | 定位 |
| --- | --- | --- |
| **系统管理员** | `User.is_superuser=true` | 平台老板/运营, 全部权限, 全部门店 |
| **门店管理员** | `Staff.role='store_admin'` + 必填 `store_id` | 店长, 本店全权 |
| 普通用户 | 其余一切账号 | 无后台权限(含废弃角色, fail-closed) |

权限点(`app/api/permissions.py`, 单一事实来源, 加权限只改矩阵):

| 功能 | 系统管理员 | 门店管理员 |
| --- | :-: | :-: |
| 工作台 / 会员 / 工单(数据范围) | 全局 | **仅本店**(后端强制) |
| 资料审核(线上) | ✅ | ❌ |
| 实名认证(线下当面核验) | ✅ | ✅ 本店 |
| 编辑/代录会员资料 | ✅ | ✅ 本店 |
| 查看联系方式(记审计) | ✅ | ✅ 本店 |
| 封禁 / 解封会员 | ✅ | ✅ 本店 |
| 赠送解锁次数 | ✅ | ✅ 本店 |
| 撮合工单处理 | 全部 | 本店工单 |
| 工单改派 / 门店 CRUD / 指定主属门店 | ✅ | ❌ |
| 管理员账号 / 门店管理员账号 / 操作日志 / 平台设置 | ✅ | ❌ |

## 3. 模块规格与实现状态

### 3.1 工作台 `/dashboard` 🟡(重做为待办驱动)

现状: 数字陈列。目标: 登录第一眼知道今天干什么。

- **待办卡**(点击直达队列): 待审资料 N / 待处理工单 N / 待实名 N / 未处理反馈 N / pending>48h 工单标红。门店管理员只看本店口径(后端按 actor 门店过滤)。
- **核心指标**: 今日注册 / 今日活跃 / 累计会员 / 审核通过率 / 撮合成功率。
- **最近动态**: 最近注册、最近提审、最近工单各 5 条。
- 实现: 扩展现有 `/admin/stats`(已含 pending 指标), 补 `store_id` 口径参数与动态流接口。

### 3.2 会员管理 `/members` + `/members/$userId` ✅

- 列表: 寻缘号/姓名/性别年龄/所属门店/审核/实名/余额/账号状态/最近活跃; 筛选(审核/实名/账号/门店/性别)+搜索(寻缘号/姓名/手机号)。
- **会员 360° 详情**: 资料/择偶要求/联系方式(脱敏+查看记审计)/权益流水/行为记录/工单历史/操作日志 Tab; 顶部操作条(审核/实名/封禁/指定门店/赠送)按角色显隐。
- 门店管理员进入 = 列表与详情自动限本店。

### 3.3 审核中心 `/review` ✅

- 资料审核队列(仅总部): 左右对照 + 通过/驳回(必填理由, 回传小程序)。
- 实名认证队列: 总部远程通过; 门店管理员当面核验后通过(记 `verified_by_store_id`), 仅本店名单。

### 3.4 撮合工单 `/requests` ✅

状态机:

```
pending ─┬─ accepted(对方同意) → contacted(已建群) → closed
         └─ rejected(对方拒绝) → closed
```

- 按状态分 Tab; 双方会员摘要卡可点开 360°; 工单按发起方门店归属, 总部可改派; pending>48h 标红; 处理时间线(handled_by/at/note)。

### 3.5 门店体系 `/stores` + `/stores/$storeId` ✅

- 列表: 增删改查 + 店照; 行内"管理员"入口进店。
- **门店工作台**(本店视角): 本店会员(完整会员表格) / 本店工单 / 管理员(进店直接建账号, 自动绑店)。
- 下一步(P1): 工作台补"本店指标卡"(会员数/待审/工单成交), 让进店即见经营全貌。

### 3.6 权益管理 `/balance` ⬜(仅总部)

- 统一流水列表: `BalanceTransaction`(注册赠送/后台赠送/解锁消耗/工单消耗/退还), 按会员/类型/时间筛选。
- 赠送: 单发(现有, 迁入) + **批量赠送**(按筛选圈人, 如"全部已实名会员+2")。
- 预留支付: 流水已有 `source`, 未来订单只是多一种 source。

### 3.7 意见反馈 `/feedback` 🟡

- 现状: 仅列表。
- 补齐: 状态流 `open → handled`, 处理备注 + 处理人/时间(模型加 `admin_note/handled_by/handled_at`); 可点开会员 360°; 工作台待办接入未处理数。

### 3.8 数据统计 `/stats` ⬜

- 趋势: 注册/活跃/提审/通过/工单量(按日/周)。
- 转化漏斗: 注册 → 完善资料 → 审核通过 → 发起/收到工单 → 撮合成功。
- 门店对比: 各店会员/实名/工单成交率(门店管理员仅本店)。
- 实现: `/admin/stats` 扩展按日聚合接口, 不引入额外 BI 组件。

### 3.9 平台设置 `/qualifications` 🟡

- 资质图片 ✅。
- 补齐: 公告/协议文案(用户协议/隐私/门店协议/退款说明)用 SiteSetting key-value 管理, 小程序端读取——**改文案不用发版**。

### 3.10 系统管理 ✅

- **管理员账号** `/admins`: 创建/停用启用(软删)/重置密码; 保护: 不能停自己/最后超管; 全操作审计。
- **操作日志** `/audit-logs`: 全局审计流, 按动作筛选 + 分页; 会员维度日志在 360° 详情内。
- 审计动作清单: audit_pass/reject, verify/unverify, block/unblock, grant_balance, view_contact, update_profile, assign_store, handle/assign_ticket, create/disable/enable_admin, reset_admin_password。

## 4. 状态机汇总

| 对象 | 状态流 | 触发者 |
| --- | --- | --- |
| 资料 | none → pending → approved / rejected(可重新提审) | 会员提审 → 总部审核 |
| 实名 | none → pending → passed / rejected | 会员申请 → 总部或本店核验 |
| 工单 | pending → accepted/rejected → contacted → closed | 会员发起 → 店长/总部处理 |
| 反馈 | open → handled | 会员提交 → 总部处理 ⬜ |
| 会员账号 | active ⇄ blocked | 总部或本店封禁/解封 |
| 管理员/门店管理员账号 | active ⇄ disabled(软删) | 系统管理员 |

## 5. 安全与审计底线(全部已落地, 新功能必须遵守)

1. 鉴权链: 后台一律 `get_current_actor`; 系统级操作 `require_perm(...)`; 未知角色 fail-closed。
2. 门店数据范围在后端强制(`_store_owner_id` / `_check_member_scope`), 前端隐藏只是体验优化。
3. 敏感操作(看联系方式/赠送/封禁/账号变更)必须 `_audit()` 留痕。
4. 用户/账号类数据只软删不硬删; 审计日志不可删。
5. 每个新后台功能: 权限点先登记 `permissions.py` 矩阵 + 矩阵单测同步。

## 03 · 数据库设计

> 最后对账: 2026-09-07, 与 app/models.py @ 当前 HEAD 对齐

数据库为 **PostgreSQL**（测试环境 SQLite 内存库），ORM 为 SQLModel，结构变更一律走 Alembic 迁移（`upgrade head` / `downgrade -1` 必须可回滚）。

### 命名约定
- 表名由 SQLModel 按类名小写生成（如 `ContactRequest` → `contactrequest`），无复数、无分隔符。
- 主键统一 `UUID`（`uuid4`），外键 `user.id` 级联删除（`ondelete=CASCADE`）。
- 列名 snake_case；时间列统一 UTC 存储（`datetime`），响应层再转北京时区。
- 大段文本在模型层不限长、在 Pydantic 入参 schema 上限长；多选字段存 `JSON` 数组。
- 软删约定：用户/订单类用 `status` + `is_active` 标记；日志/审计（`auditlog`、`balancetransaction`）不允许删。

### 表 1：`user` · 用户账号
微信小程序用户与后台管理员同表，靠 `openid`（小程序）与 `is_superuser`（后台）区分；小程序用户 `email` 可空。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | UUID PK | |
| `email` | varchar(255) | 唯一索引；管理员必填，小程序用户可空 |
| `hashed_password` | text | 可空（openid 用户无密码） |
| `is_active` / `is_superuser` | boolean | 默认 true / false |
| `full_name` | varchar(255) | |
| `openid` | varchar(64) | 唯一索引 |
| `unionid` | varchar(64) | |
| `xy_code` | varchar(16) | 寻缘号（8 位数字），唯一索引 |
| `unlock_balance` | int | 解锁/申请次数余额，默认 3 |
| `notify_enabled` | boolean | 是否订阅每日推荐 |
| `follow_official` | boolean | 是否已关注公众号 |
| `verified` | varchar(16) | 实名认证 `none/pending/passed/rejected`，默认 none |
| `status` | varchar(16) | `active / blocked`（注销为 `deactivated`、删除为 `deleted`，均伴随 `is_active=false`） |
| `last_active_at` | datetime | |
| `membership_expires_at` | datetime | 会员到期时间（冗余列，由 membershipgrant 事务内同步，判定只看此列），索引 |

### 表 8：`contactrequest` · 联系申请工单（红娘撮合）
红娘撮合方案核心表：A 想联系 B → 提交工单 → 红娘人工撮合。联系方式不直接交换。

| 字段 | 类型 | 说明 |

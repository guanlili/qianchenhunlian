# 13 · 会员体系设计（付费会员 + 每日免费额度）

> 状态：设计稿，待业务拍板（见 §12 待确认）。
> 关联：`docs/03-数据库设计.md`（schema 变更）、`docs/11-后台功能全景设计.md`（后台 UI）、`docs/12-剩余工作实施计划.md`（分期执行）。

## 0. 背景与现状

当前额度体系（已实现）：

- `User.unlock_balance`：一次性永久余额，注册赠 3 次；后台可赠送（`POST /admin/users/{id}/grant-balance`，`GRANT_BALANCE` 权限，门店管理员限本店）。
- 消耗点唯一：小程序「申请联系」工单，每次扣 1（原子 UPDATE，不足 402）。直接解锁联系方式已废弃（红娘撮合方案，联系方式永不下发客户端）。
- `BalanceTransaction` 全量流水（register_gift / admin_grant / contact_request_cost / refund），`AuditLog` 审计齐备。

痛点：额度是一次性存量，用完只能靠后台赠送；没有「每天回血」的免费额度，也没有付费会员概念，门店无法按月/年向用户收会员费。

## 1. 目标与术语

**一句话**：普通用户每天有 5 次免费申请额度（自然日重置）；付费会员（月卡/年卡/体验卡）日额度更高；门店管理员、总部管理员可给用户开通/续费/回收会员，收款在线下完成。

| 术语 | 含义 |
| --- | --- |
| 普通用户 | 注册即用，每日免费额度 5 次 |
| 付费会员（下称「会员」） | 处于有效期内的 `membership_expires_at > now` 的用户 |
| 每日免费额度 | 普通用户每个自然日可用的免费申请次数，默认 5 |
| 会员日额度 | 会员每个自然日的申请次数上限，默认 20（可配） |
| 永久余额 | 现有 `unlock_balance`，注册赠送/后台赠送累积，永不过期 |

## 2. 额度引擎（核心规则）

三桶模型，消耗顺序固定：

```
会员 → 会员日额度 ──用完──▶ 永久余额 ──用完──▶ 402
非会员 → 每日免费额度(5) ──用完──▶ 永久余额 ──用完──▶ 402
```

- 「每天」= 北京时间自然日（用户全在山东，后端 UTC 存储，判断时 +8h 取日期）。
- 日额度每日 0 点重置，不结转、不可囤。
- 会员到期即降级（下一自然动作起按普通用户判定），剩余永久余额照常可用。
- 会员期内消耗走「会员日额度」，不动永久余额（余额保值，到期后还能用）。
- 24h 内同人重复申请的防骚扰规则不变，不退额度。

**消耗落账区分桶**：`BalanceTransaction.source` 新增 `daily_free_cost` / `member_daily_cost`，与现有 `contact_request_cost`（永久余额扣减）并存，报表可分桶统计。

## 3. 数据模型（同步 docs/03）

### 3.1 User 加列（denormalized，热路径判定用）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `membership_expires_at` | TIMESTAMP NULL | 当前会员到期时间；非会员为 NULL 或 ≤ now |
| `membership_plan_code` | VARCHAR(32) NULL | 最近一次生效套餐 code（展示用，判定只看 expires_at） |

> 契约：`membership_grants` 是唯一事实来源；两列由发放/撤销事务内同步重算（取未撤销记录的最大 expires_at），避免每次扣额度都 join。按 `docs/12` 约定，加列需登记 `backend/app/core/db.py` 的 `_PENDING_ADD_COLUMNS` + alembic 迁移。

### 3.2 新表 `membership_grants`（发放记录，即会员流水）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | UUID PK | |
| `user_id` | UUID FK user, index | 被发放用户 |
| `plan_code` | VARCHAR(32) | trial_7d / monthly_30d / yearly_365d / custom |
| `days` | INT | 实际天数（custom 时自定义） |
| `source` | VARCHAR(32) | admin_recharge（充值）/ admin_trial（体验）/ admin_compensate（补偿，预留） |
| `start_from` | TIMESTAMP | 起算点 = max(now, 发放时到期时间)，支持叠加续费 |
| `expires_at` | TIMESTAMP | 本条到期时间 |
| `granted_by_type` | VARCHAR(16) | user（总部超管）/ staff（门店管理员） |
| `granted_by_id` | UUID | 操作者 id |
| `store_id` | UUID NULL FK store | 归属发放门店（经营报表用；总部发放可为 NULL） |
| `note` | VARCHAR(255) | 备注（如「线下收款 ¥299」） |
| `revoked_at` | TIMESTAMP NULL | 回收时间；非空=撤销 |
| `created_at` | TIMESTAMP index | |

索引：`(user_id, created_at)`、`(store_id, created_at)`。

### 3.3 新表 `daily_quota_usage`（日额度计数）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `user_id` | UUID FK user | |
| `date` | DATE | 北京时间自然日 |
| `used` | INT | 当日已用日额度次数（仅计走日额度的消耗，永久余额扣减不在此计数） |

PK 为 `(user_id, date)`，消耗时 upsert 原子 +1，当日上限 = 会员 ? 会员额度 : 免费额度。

### 3.4 SiteSetting 配置 `membership.plans`

```json
{
  "free_daily_quota": 5,
  "member_daily_quota": 20,
  "plans": [
    { "code": "trial_7d",    "name": "7天体验卡", "days": 7,   "price": null },
    { "code": "monthly_30d", "name": "月卡",      "days": 30,  "price": 99  },
    { "code": "yearly_365d", "name": "年卡",      "days": 365, "price": 499 }
  ],
  "trial_once_per_user": true
}
```

价格仅作展示（小程序介绍页/后台参考），收款在线下，后台开通。改配置即改行为，无需发版。

## 5. 后台 API（契约以 Swagger /docs 为准）

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| POST | `/admin/users/{user_id}/grant-membership` | 开通/续费：body `{plan_code, days?, source, note?}`；days 缺省取套餐，custom 必填；叠加续费 start_from=max(now, 现到期) | `MEMBER_GRANT`（新）门店限本店 |
| POST | `/admin/membership-grants/{grant_id}/revoke` | 回收误发：body `{reason}`；撤销后重算 User 会员列 | `MEMBER_GRANT` |
| GET | `/admin/users/{user_id}/membership-grants` | 发放记录列表（时间倒序） | 会员 360° 内，随既有 scope |
| GET | `/admin/membership/plans` | 读套餐配置（发放对话框用） | 登录即读 |

- 新权限点 `MEMBER_GRANT = "member_grant"` 登记 `permissions.py` 矩阵 + 矩阵单测；superuser 全量、store_admin 本店（`_check_member_scope`，与 GRANT_BALANCE 同法）。
- 每次 grant/revoke 写 `AuditLog`（actor、target、plan、days、note）。

## 6. 小程序 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/membership/me` | `{is_member, expires_at, plan_name, quota: {date, limit, used, remaining, bucket}, balance}`；bucket=free/member 告知当前走哪个桶 |

- 「申请联系」现有扣减点改造为三桶引擎；402 响应体带 `code: "QUOTA_EXHAUSTED"`，前端区分引导文案（开通会员/联系红娘）。
- 现有 `GET /contacts/quota` 兼容保留，内部改为聚合新引擎（返回值加字段不删字段）。

## 7. 管理后台 UI（admin console）

- **会员 360° 详情**（`/members/$userId`）：
  - 顶部「会员状态卡」：是否会员 / 套餐 / 到期时间（临近到期标橙）/ 今日额度用量 / 永久余额。
  - 操作条新增「开通/续费会员」：对话框选套餐（或 custom 天数）+ 发放类型（充值/体验/补偿）+ 备注；提交调 grant 接口。
  - 新 Tab「会员记录」：发放/撤销流水（谁、何时、哪家店、天数、备注）。
- **会员管理列表**（`/members`）：加「会员」列（徽标：会员/7天内到期/非会员）+ 筛选项。
- P2：**会员经营报表**（各店会员数、新增、到期分布、续费率），进门店工作台指标卡。

## 8. 小程序 UI

- 「我的」页：会员卡片（状态/到期/今日剩余额度/永久余额），非会员显示引导（P2 做介绍页，价格从配置下发）。
- 申请联系弹窗：额度提示升级为「今日免费剩余 X 次 / 会员今日剩余 X 次 + 余额 Y 次」。
- P2：到期前 3 天订阅消息提醒（需模板审批）。

## 9. 边界与并发

| 场景 | 处理 |
| --- | --- |
| 并发扣减 | 沿用 contacts.py 现有原子 UPDATE 模式：日额度 upsert 计数带 `WHERE used < limit` 条件，失败再走余额原子扣，双双失败 402 |
| 叠加续费 | start_from = max(now, 当前 expires_at)，新记录到期自然顺延 |
| 撤销后重算 | revoke 将该 grant 标记 revoked_at，重算 User 两列（取剩余未撤销记录 max expires_at） |
| 体验卡重复发放 | `trial_once_per_user=true` 时校验该用户无未撤销的 trial 记录 |
| 会员期跨天 | 按「动作发生时刻」判定身份：当天前 3 次走会员桶、到期后第 4 次走免费桶是合法状态 |
| 封禁用户 | 会员状态保留但无法产生消耗（现有 status 校验拦截） |
| 误发跨店 | 门店管理员只能发本店会员（home_store_id 校验），总部不限 |

## 10. 分期实施

- **P1（后端+后台，先行）**：额度引擎 + membership_grants + 日额度表 + 后台发放/撤销/记录 + 会员状态卡 + 列表徽标。旧 `unlock_balance` 语义不变。
- **P2（小程序+报表）**：我的会员卡、申请弹窗升级、会员介绍页、经营报表、到期提醒。
- **P3（远期）**：微信支付自助购买（新增 source=wx_pay 的 grant 记录 + 支付回调），套餐管理后台化。

## 11. 不做的事

- 一期不做邀请得额度、不做额度转账、不做自动续费扣款。
- 不改变红娘撮合方案：会员也不直接看联系方式，会员权益只是额度与后续可扩展的增值项。
- 不建 Role/Plan 表做复杂权益矩阵——套餐用一个表 + SiteSetting 配置，够用且可演进。
